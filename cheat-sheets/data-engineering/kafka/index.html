Apache Kafka — Interview Cheat Sheet

Core concepts for streaming interviews — from producers to exactly-once semantics.

Interview tip Draw: Producer → Topic (partitions) → Consumer Group. Mention offset, replication factor, and why partitions enable parallelism.

Core concepts

TermOne-liner
TopicLogical stream of records, split into partitions
PartitionOrdered, immutable log — parallelism unit
OffsetPosition in partition log — consumer tracks this
Consumer groupOne consumer per partition max — scale reads
ReplicationLeader + followers (ISR) — fault tolerance
BrokerKafka server storing partitions

Architecture diagram

Kafka cluster (simplified)
Producers→ Brokers / Topics→ Consumer Group
  • Key-based routing: same key → same partition (ordering per key)
  • Zookeeper/KRaft: cluster metadata & controller election
  • Retention: time or size based — not a traditional queue

Delivery semantics

SemanticHowTrade-off
At-most-onceCommit offset before processMay lose messages
At-least-onceProcess then commit offsetDuplicates possible
Exactly-onceIdempotent producer + transactionsMore overhead

Common interview questions

  • How do you handle consumer lag? (scale consumers ≤ partitions, optimize processing, monitor)
  • Partition count — how to choose? (throughput vs ordering vs rebalancing cost)
  • Kafka vs traditional MQ? (log-based, replay, high throughput)
