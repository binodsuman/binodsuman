Apache Spark — Interview Cheat Sheet

Batch and streaming processing essentials for data engineering interviews.

Interview tip Explain lazy evaluation: transformations build DAG → action triggers execution. Mention driver, executors, and shuffle as bottleneck.

Spark building blocks

Driver — SparkContext, DAG scheduler
Executors — run tasks, store cache
Cluster Manager — YARN, K8s, standalone
APIUse

DataFrame/DatasetStructured — Catalyst optimizer
Spark SQLSQL on DataFrames + Hive support

Transformations vs actions

Transformations (lazy): map, filter, join, groupBy — build lineage.
Actions: count, collect, save — trigger job.
Wide deps: shuffle (groupBy, join) — expensive — minimize!
Shuffle
Map tasks→ Shuffle / Sort→ Reduce tasks

Tuning checklist

  • Partitions: default 200 — increase for large data, avoid tiny files
  • Memory: executor memory + overhead, spill to disk if OOM
  • Broadcast join: small table broadcast to avoid shuffle
  • Cache: persist() for reused DataFrames — MEMORY_AND_DISK
  • Structured Streaming: micro-batch or continuous processing

Spark vs MapReduce

In-memory lineage, 10–100× faster for iterative jobs. Fault tolerance via RDD lineage recomputation (not HDFS replication per step).
