System Design

System Design Interview Patterns

The 6 designs that cover 80% of interview questions — with architecture sketches.

Interview tip Name the pattern: "This is read-heavy → CDN + cache. Writes are bursty → queue + async workers."

1. URL Shortener

POST /shorten→ Hash / counter ID→ DB mapping
Key: base62 encoding, collision handling, redirect GET is cacheable, analytics optional via async queue.

2. Chat / messaging

Real-time chat
WebSocket→ Chat service→ Message queue→ DB + push
Mention: presence (online), delivery guarantees (at-least-once), fan-out for groups, partition by conversation ID.

3. Rate limiter

Token bucket: tokens refill at rate R, burst allowed.
Sliding window: more accurate, use Redis + sorted sets.
Where: API gateway or sidecar — return 429 + Retry-After header.
