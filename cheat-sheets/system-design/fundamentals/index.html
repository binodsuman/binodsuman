System Design Fundamentals

Core building blocks every senior interview expects — explained like handwritten revision notes.

Interview tip Start every answer: requirements (functional + non-functional) → estimate scale → high-level diagram → deep dive 2 components → trade-offs.

Scalability basics

  • Vertical scale: bigger machine — simple but has limits
  • Horizontal scale: more machines — needs load balancing & shared state strategy
  • Stateless services: session in Redis/DB — easier to scale out
  • Back-of-envelope: 1M DAU × 10 req/day = ~116 req/s average (plan for 10× peaks)
Request path
Client→ CDN→ Load Balancer→ App Servers→ Cache→ Database

CAP: Pick 2 of Consistency, Availability, Partition tolerance. CP = strong consistency (banking). AP = availability (social feeds).

Caching strategies

  • Cache-aside: app reads cache → miss → read DB → write cache
  • Write-through: write cache + DB together — consistent but slower writes
  • TTL: always set — prevents stale forever
  • Eviction: LRU common; watch hot-key problem
