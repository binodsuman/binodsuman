① What you must know (30 sec)

Build your first agent by combining one LLM, one tool, and a simple while-loop. The weather-bot pattern — user asks a question, model calls get_weather(city), result returns to the model, model answers — teaches everything you need before scaling to multi-tool agents.
Analogy: Training wheels: one tool is like learning to ride with stabilizers before tackling a multi-tool BMX course.

② How it works

First agent architecture
User: weather in Paris?→LLM → get_weather→API returns 18°C→LLM final reply
Minimum viable agent: tool definitions in the API call, loop until stop_reason is final or step limit hit.
Test the tool function independently before wiring it to the LLM — unit test the API wrapper first.

③ Step-by-step (hands-on)

Step 1 — Pick one concrete tool

Weather API, stock price, or internal "get_user_by_email" — something with a clear JSON request/response you can mock.

Step 2 — Write the tool schema

{"name":"get_weather","description":"Current weather for a city","parameters":{"type":"object","properties":{"city":{"type":"string"}},"required":["city"]}}

Step 3 — Implement the function

Python def get_weather(city) -> str that calls the API, handles 404, returns a short string the LLM can read.

Step 4 — Craft the planner prompt

"You have get_weather. Return a tool call to answer weather questions. For greetings, reply directly without tools."

Step 5 — Build the loop

messages = [system, user]; while steps < 5: response = llm(messages, tools); if no tool: return text; else run tool, append tool result.

Step 6 — Test edge cases

Invalid city, API timeout, ambiguous "here" without location — verify graceful errors in observations.

Step 7 — Add logging and limits

Print each step; set timeout; track total tokens. Only then add a second tool.

④ Code / config patterns

Tool schema tips: Description is what the model reads — be explicit: "City name in English, e.g. London, UK. Do not pass coordinates." Include enum for fixed choices. Mark required fields. Bad descriptions cause wrong tool selection more than bad code.
TOOLS = [{"type": "function", "function": {
  "name": "get_weather",
  "description": "Get current weather for a city name",
  "parameters": {"type":"object","properties":{"city":{"type":"string"}},"required":["city"]}
}}]

def run_agent(user_msg):
    messages = [{"role":"system","content":PLANNER_PROMPT},
                {"role":"user","content":user_msg}]
    for _ in range(5):
        r = client.chat.completions.create(model="gpt-4o-mini", messages=messages, tools=TOOLS)
        msg = r.choices[0].message
        if not msg.tool_calls:
            return msg.content
        for tc in msg.tool_calls:
            result = get_weather(**json.loads(tc.function.arguments))
            messages.append({"role":"tool","tool_call_id":tc.id,"content":result})
    return "Sorry, I could not complete that."

⑤ Production & pitfalls

PitfallWhy it hurtsFix
Too many tools on day oneConfused planner, flaky demosStart with one tool; add second only when first is reliable
Vague tool descriptionsModel calls wrong tool or bad argsExamples in description; test with 20 prompts
No independent tool testsCannot tell if bug is LLM or APIUnit test tool functions with mocks first
Parsing free-text actionsFragile JSON extractionUse native tool/function calling API
Missing error in observationModel hallucinates successReturn "Error: city not found" as tool output
No step limitInfinite loop on stuck taskHard cap at 5 steps for first agent
Production tips:
  • Wrap external API calls with circuit breaker and caching
  • Return structured tool errors the model can relay to users
  • Version tool schemas; breaking changes need migration

⑥ Interview / on-the-job Q&A

QuestionAnswer
First tool to build?Read-only lookup with clear params — weather, stock, or internal GET endpoint.
Why JSON schema?Provider validates structure; model knows required fields and types.
What goes in observation?Concise tool output string or JSON — not raw HTTP dumps.
How many steps for v1?5 is enough for weather; increase only with eval evidence.
Framework or raw loop?Raw loop teaches fundamentals; framework when you need persistence and branching.
How test the agent?Script of 15 prompts: happy path, invalid input, no-tool chitchat, API failure.

⑧ Revision checklist

  • One tool with tested API wrapper
  • JSON schema with clear description and required fields
  • Planner system prompt explains when to use tool vs answer directly
  • Loop with max 5 steps implemented
  • Tool errors returned as observations, not exceptions
  • Each step logged (tool name, args, result length)
  • 15-prompt manual test script passes
  • Timeout on external API calls
  • Second tool deferred until first is stable
